# Retake Notes — 影片修改註記系統

類似 Frame.io 的 retake note 網站。網站放在 GitHub Pages，資料存在你自己的 Google Sheet，透過 Google Apps Script 讀寫，用「帳號＋PIN 碼」登入。

## 功能

| 類別 | 功能 |
|---|---|
| 播放器 | 逐格前後跳、Timecode／格數即時顯示、自動偵測 fps 與總格數（讀 MP4 檔頭）、起始 TC 偏移（如 01:00:00:00）、Drop-frame、輸入 TC 跳轉、時間軸註記標記、J／K／L、變速 0.1×–2×、入出點區段循環、安全框／比例遮罩／三分線、全螢幕 |
| 註記 | 單格或區段（I／O）註記、畫筆（支援繪圖板壓感）、箭頭、方框、圓圈、定位點、6 色、復原／重做、自動截圖（含畫記）、回覆串、附加參考圖片（可直接貼上）、內部私人註記、@提及、#標籤、篩選與搜尋 |
| 版本 | 版本堆疊 v1／v2／v3、新版本沿用未解決的註記、兩個版本並排同步比對 |
| 協作 | 管理者／專案負責人／Acer同事／廠商四種角色、新帳號的 PIN 可自動產生並用 Email 寄給對方、第一次登入必須先改 PIN、專案負責人只管自己負責的專案、Acer同事與廠商只看得到被加入的專案、註記狀態（待修改→修改中→已修改→已確認／不修改）、版本核准、指派負責人、截止日、進度儀表板、我的待辦、Email 通知、免帳號分享連結（可設密碼、到期日、能否留言）、浮水印 |
| 匯出 | Excel（總覽＋註記明細＋嵌入截圖＋討論紀錄）、PDF（瀏覽器列印另存） |
| 字幕 | 載入 SRT／VTT（只在本機讀取，不上傳）、疊在畫面上同步播放、逐句列表點選跳轉、自動檢查（重疊、間隔、顯示太短／太長、閱讀速度、每行字數、行數、超出影片長度）、一鍵把某句字幕加為註記；**自動產生字幕**（語音辨識，在本機執行不上傳）、逐句修改文字與入出點、匯出 SRT |
| 聲音 | 播放時即時音量表（L／R 峰值 dBFS、峰值保持、爆音燈）並記錄超標時間點；整段分析（不用播放）：峰值、True Peak、整合響度 LUFS、列出所有超過上限的時間點 |
| 影片來源 | 本機檔案（不上傳）或雲端連結（Google Drive、Dropbox、任何 mp4 網址），新增版本時選擇 |

## 檔案結構

```
retake-notes/
├─ index.html
├─ css/app.css
├─ img/acer-logo-white.png  ← Acer 白色 logo（標題列用）
├─ js/
│  ├─ config.js     ← 唯一需要修改的設定檔（API_URL）
│  ├─ core.js       ← 共用核心邏輯（同時貼到 Apps Script 的 Core.gs）
│  ├─ api.js        ← 連線層＋試用模式
│  ├─ mp4.js        ← 讀取 MP4 的 fps／格數
│  ├─ player.js     ← 逐格播放器、安全框、截圖
│  ├─ media-tools.js ← 字幕解析與檢查、音量表、聲音分析
│  ├─ asr.js        ← 自動字幕：切段、整理成字幕句子、SRT
│  ├─ asr-worker.js ← 自動字幕：在背景執行 Whisper 語音辨識
│  ├─ annotate.js   ← 畫記
│  ├─ export.js     ← Excel／PDF
│  ├─ app.js        ← 登入、儀表板、專案、帳號、分享
│  └─ review.js     ← 審閱頁
└─ apps-script/Code.gs
```

## 先試用（不需要任何設定）

`js/config.js` 的 `API_URL` 留空時是**試用模式**：所有資料只存在這台電腦的瀏覽器裡，別人看不到。

- 管理者：`admin` / `1234`
- 廠商：`studio_a` / `5678`
- Acer同事：`acer_amy` / `2468`
- 專案負責人：`pm_lin` / `1357`（負責「品牌形象短片」）、`pm_chen` / `9753`（負責「產品開箱影片」）

想清掉試用資料：右上角使用者選單 →「清除試用資料」。

## 正式部署

### 1. 建立 Google Sheet 與 Apps Script

1. 到 Google 雲端硬碟建立一個新的試算表，例如「Retake_Note_System」。
2. 選單「擴充功能」→「Apps Script」。
3. 把預設的 `程式碼.gs` 內容換成 `apps-script/Code.gs` 的內容。
4. 左側「檔案」旁的 ＋ →「指令碼」，命名為 `Core`，把 **`js/core.js` 整份內容**貼進去。
5. 修改 `Code.gs` 最上面的 `CONFIG`：
   - `ADMIN_USERNAME`／`ADMIN_PIN`：第一個管理者帳號
   - `SITE_URL`：之後的 GitHub Pages 網址（通知信裡的連結會用到，可以晚點再填）
6. 上方函式選單選 `setup` →「執行」→ 依指示授權（會用到試算表、雲端硬碟、寄信）。
   執行完成後，試算表會出現 Users、Projects、Versions、Notes、Replies、Shares、Files 七個工作表。
7. 右上「部署」→「新增部署作業」→ 類型選「網頁應用程式」：
   - 執行身分：**我**
   - 誰可以存取：**所有人**
8. 複製「網頁應用程式網址」（`https://script.google.com/macros/s/…/exec`）。

> 「所有人」是讓網站能呼叫 API，資料仍需要帳號＋PIN 才能讀取；截圖與附件存在你雲端硬碟的私人資料夾，只透過 API 提供給有權限的人。

### 2. 設定網站

把剛才的網址貼到 `js/config.js`：

```js
API_URL: 'https://script.google.com/macros/s/xxxxxxxx/exec',
```

### 3. 放上 GitHub Pages

1. 在 GitHub 建立新的 repository（例如 `retake-notes`）。
2. 把 `retake-notes` 資料夾裡的檔案上傳（`apps-script/` 與 `README.md` 可以不放）。
3. Settings → Pages → Source 選 `Deploy from a branch`，Branch 選 `main`／`/ (root)` → Save。
4. 約一分鐘後就能用 `https://你的帳號.github.io/retake-notes/` 開啟。
5. 回到 Apps Script，把這個網址填進 `CONFIG.SITE_URL`，然後「部署」→「管理部署作業」→ 編輯（鉛筆）→ 版本選「新版本」→ 部署。

### 4. 開始使用

1. 用管理者帳號登入。第一次登入會要求你先把預設 PIN 換成自己的 PIN。
2. 「帳號管理」→ 新增帳號：選角色（專案負責人／Acer同事／廠商），填對方的 Email，PIN 留空會自動產生，勾「用 Email 把 PIN 寄給對方」就會寄出帳號、PIN 與網址。沒有寄出的自動 PIN 只會在畫面上顯示一次，請自行轉交。對方第一次登入（或你之後幫他重設 PIN）時，系統會要求他先改成自己的 PIN 才能使用。
3. 「專案」→ 新增專案，勾選專案負責人與參與的 Acer同事、廠商。專案負責人也可以自己建立專案（自動成為負責人）和 Acer同事／廠商帳號。
4. 專案頁「新增版本」→ 選本機檔案或貼雲端連結 → 開始審閱。
5. 把網址和帳號／PIN 給廠商；或在專案頁建立「免帳號分享連結」給客戶。

### 之後修改程式

- 改了 `Code.gs` 或 `core.js`：Apps Script 的 `Core.gs` 也要更新成新的 `core.js`，然後「管理部署作業」→ 編輯 →「新版本」（網址不會變）。資料欄位有增加時（例如 v1.2.0 的 `mustChangePin`、v1.3.0 的 `createdBy`），更新程式後再執行一次 `setup`，它只會補上缺少的欄位，不會動到既有資料。
- 忘記管理者 PIN：Apps Script 編輯器選 `resetAdminPin` →「執行」，新 PIN 會顯示在下方「執行記錄」；用它登入後網站會要求你改成自己的 PIN。
- 改了網站檔案：重新上傳到 GitHub，並把 `index.html` 裡所有 `?v=20261126-3` 換成新的版本字串，避免瀏覽器快取到舊檔。
- 發佈新功能時，把 `js/app.js` 最上面的 `RT.VERSION` 改成新版本號，標題列會自動顯示。

## 影片來源

| 方式 | 說明 |
|---|---|
| **本機檔案** | 檔案不會上傳，逐格最精準、免費。每個人要在自己電腦上有**同一個輸出檔**；系統會比對檔名與大小，不一致時會提醒。 |
| **Google Drive** | 檔案共用設為「知道連結的人都能檢視」，貼上分享連結即可。Google 會擋其他網站直接播放雲端硬碟的下載連結，所以 `config.js` 必須填 `GOOGLE_API_KEY`（已設定：Google Cloud 專案 retake-notes，帳號 acervideoteam；金鑰限制只能從 `https://photovideoteam.github.io/*` 使用、只能呼叫 Drive API）。網站網址若改變，要到 Google Cloud 控制台 →「API 和服務」→「憑證」把新網址加進金鑰的網站限制。 |
| **Dropbox** | 貼上分享連結，系統會自動轉成直接播放的網址。 |
| **其他網址** | 任何可以直接播放的 `https://…mp4`。伺服器若不允許跨網域讀取，仍可播放與註記，但無法自動截圖。 |

建議輸出 **H.264 MP4、固定幀率 (CFR)**。ProRes／DNxHD 等格式瀏覽器無法播放；H.265 要看瀏覽器與顯示卡支援。

## 限制與注意事項

- Apps Script 每次請求約 1–2 秒；審閱頁每 30 秒自動更新註記（`config.js` 的 `REFRESH_SECONDS`）。
- 一般 Gmail 帳號每天約可寄 100 封通知信（Google Workspace 帳號較多）。不需要通知可在 `CONFIG.MAIL_ENABLED` 關閉，或在個別帳號取消勾選。
- 登入有效 6 小時；同一帳號 PIN 連錯 5 次會鎖 15 分鐘。
- 「沿用註記」是依**格數**對應。新版本若剪接有變動，沿用的註記位置可能需要手動調整（註記上的「編輯」可以改入出點）。
- GitHub Pages 的程式碼是公開的，但資料都在你的 Google Sheet，必須登入才能讀取。

## 自動字幕

審閱頁「字幕」分頁 →「自動產生字幕」。用 OpenAI 開源的 Whisper 模型（透過 transformers.js）在瀏覽器裡辨識，**聲音不會上傳**，也不需要後端或付費 API。

| 模式 | 模型 | 第一次下載 | 說明 |
|---|---|---|---|
| 快速 | whisper-base | 約 210 MB（沒有 WebGPU：約 80 MB） | 速度最快，中文錯字較多 |
| 標準 | whisper-small | 約 410–590 MB（沒有 WebGPU：約 250 MB） | 平衡 |
| 準確 | whisper-large-v3-turbo | 約 760 MB | 最準，需要 WebGPU（Chrome／Edge＋顯示卡） |

- 模型下載一次後留在瀏覽器快取；之後每次打開審閱頁仍需要十幾秒把模型載入顯示卡。
- **語言**：整支影片只有一種語言時直接選語言最準。選錯語言（例如中文模式遇到整句英文）會被翻譯成選的語言；中英夾雜可選「自動偵測」，但較不穩定。
- 中文結果會自動轉成台灣繁體（OpenCC），逗號句號改成空格，並依「檢查規則」的每行字數切句。
- **詞彙修正**：產品名稱常被聽錯（例如「宏碁」→「宏奇」），可在對話框的「詞彙修正」設定「聽錯的字=正確的字」，辨識完自動取代（只存在這台電腦）。
- 時間點誤差約零點幾秒，會自動對齊到有聲音的地方；有背景音樂時對齊效果較差。
- 結果一定要校對：每句的 ✎ 可以改文字、把入點／出點設為目前畫面、刪除；「＋ 新增一句」可補漏掉的句子；改完按「匯出 SRT」（UTF-8 含 BOM，Premiere／Resolve 可直接匯入）。修改只存在這台電腦。
- 雲端連結的影片會整個下載到記憶體再辨識；很長或很大的檔案（例如一小時以上的母帶）可能記憶體不足，建議用壓縮過的審閱檔。
